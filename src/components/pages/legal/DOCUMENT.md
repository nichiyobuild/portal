## ファイル構成

| ファイル | 役割 |
| --- | --- |
| `index.tsx` | 公開ページ本体 |
| `legal-table.tsx` | 表示事項の表。公開ページとダウンロードファイルで共用する |
| `disclosure-request-form.tsx` | 省略事項を含む全文を請求するフォーム |
| `legal-disclosure-document.tsx` | 請求に応じて提供する電磁的記録 |
| `disclosure-error.tsx` | Turnstile 検証に失敗したときの画面 |

`legal-table.tsx` を公開ページとダウンロードファイルの両方で使っているのは、
両者の内容がずれないようにするため。`disclosed` プロパティの有無だけで
省略事項の表示が切り替わる。**片方だけ直さないこと。**

## 電話番号と運営統括責任者名を省略している根拠

法11条ただし書により表示を省略している。消費者庁の省略可否一覧で、いずれも
価格の表示状況にかかわらず「省略できる」とされている事項。

条文上も、規則25条1項・2項が省略の対象外としているのは規則23条6号〜10号であり、
氏名・住所・電話番号（23条1号）と代表者名（23条2号）は法11条6号に含まれるため
対象外の列挙に入っていない。

### 省略が適法になる条件

次の2つを**どちらも**満たす必要がある。

1. 請求により広告表示事項を遅滞なく提供する旨を、この表記に明示すること
   （欄を削除・空欄にするだけでは要件を満たさない）
2. 実際に請求があったとき「遅滞なく」提供できる措置を講じていること

同ガイドは、この「遅滞なく」を「申込みの意思決定に先立って十分な時間的余裕を
もって提供されること」と定義する。即決で購入されるデジタルコンテンツでは、
有人対応の「3営業日以内」では足りない。

条件2は、Turnstile 通過後に全文をその場でダウンロードさせる方式で満たしている
（`disclosure-request-form.tsx` と `legal-disclosure-document.tsx`）。同期的に
提供が完結するため、メール送信のように到達性や受信確認に左右されない。

> [!WARNING]
> ダウンロードのエンドポイントは **POST のみ**。GET を実装するとクローラーが
> 到達でき、電話番号と代表者名が検索インデックスに載る。静的ファイルとして
> 配置するのも同じ理由で不可。

> [!WARNING]
> 電話番号と代表者名は Worker Secret（`LEGAL_PHONE_NUMBER` /
> `LEGAL_REPRESENTATIVE_NAME`）から読む。過去に git 履歴から実名を削除している
> ため、**コードに書き戻さないこと**。未設定のままデプロイすると、配布する
> ファイルの該当欄が `undefined` になる。

## 省略できない事項

省略可否一覧で「省略できない」とされている事項は、表から外さないこと。
規則25条1項・2項はいずれも規則23条6号〜10号を省略の対象外としている。

- 動作環境（規則23条6号）
- 返品に関する事項
- 販売数量の制限等（規則23条8号）
- 月額制で必要になる「契約を2回以上継続して締結する場合の販売条件」（規則23条7号）

## 行の並び順

法11条各号 → 同条6号を受けた規則23条各号の順に揃えている。項目を足すときも
この順序を崩さないこと。各行の根拠は `legal-table.tsx` のコメントを参照。

返品・交換・キャンセルの行だけ体裁を変えているのは、規則24条3号が
「顧客にとつて見やすい箇所において明瞭に判読できるように」表示することを
求めているため。他の行と同じ見た目にしないこと。

## 未実装の機能に伴い、将来この表記の更新が必要になる事項

### TODO(サブスク): 月額プランの金額を明記する

月額プランの内容が決まったら、金額をこの表に明記すること。規則23条7号は
「二回以上継続して締結する必要があるときは、その旨及び金額、契約期間その他の
販売条件」を求めており、規則25条の省略対象外。

現状の「契約期間および自動更新」「解約の方法」の行は金額を欠いているため、
購入画面任せにせず、月額料金をここに書く必要がある。

### TODO(課金実装): 法12条の6（特定申込みを受ける際の表示）に対応する

申込みの最終確認画面に「役務の分量」（サブスクなら契約期間・自動更新の有無）と
法11条1号〜5号の事項を表示する義務がある。同条2項は申込みとなることを
誤認させる表示も禁じている。

Stripe Checkout の標準画面だけでは1号の「分量」を満たさない可能性が高く、
自サイト側に確認画面が要る。これはこのページではなく購入フロー側の課題。

### TODO(期間限定販売): 「申込みの有効期限」の行を追加する

期間限定アイテムやセールを始めるときに必要。法11条4号の「申込みの期間に関する
定めがあるときは、その旨及びその内容」に当たる。

規則25条1項・2項の省略可能事項の列挙から **4号だけが外れており**、定めがあれば
省略できない。

### TODO(メール広告): 電子メールアドレスを明記する

新作やセールの案内をメール配信するときに必要（規則23条10号・省略対象外。
問い合わせフォームへのリンクでは代替できない）。

あわせて法12条の3のオプトイン規制と、規則30条の承諾記録の保存義務が発生する。
規約変更やサービス停止の通知は「通信販売電子メール広告」に当たらないため、
現状の運用では不要。

### 価格をこの表に載せる場合

規則25条1項（金銭を全部表示しない場合）から2項に適用が切り替わり、
契約不適合責任の定め（規則23条5号）の記載が新たに必要になる。
`terms.tsx` 第11条1項に「瑕疵がないことを保証していません」という定めがあるため。
